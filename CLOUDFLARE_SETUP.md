# PG Hunter — Cloudflare Backend Setup

PG Hunter's backend runs on **Cloudflare Workers + D1** (the locked architecture
in `/ai/MASTER_ARCHITECTURE.md`). The Astro site and the `/api/*` endpoints
deploy together as one Worker, so everything is same-origin and no tokens ever
touch the browser — auth is a plain `httpOnly` cookie.

What the backend does today:

- **Email + password auth** (PBKDF2-hashed passwords, session cookies)
- **Google sign-in** (manual OAuth 2.0 — no hosted auth provider)
- **Profile updates** (name / phone / college)
- **Saved PGs** (per-user shortlist)
- **Enquiries** (leads table)
- **Owner dashboard** — create/edit/submit PG listings, upload photos + documents (R2), verification status, enquiry inbox
- **Owner verification** — upload credible documents (ID, ownership proof, etc.), admin approves/rejects them
- **Admin panel** — stats, review/approve/reject listings, review verification documents, attach YouTube room-tour videos to listings
- **Public listings API** — published (approved) listings with search/filter/sort, ready for the student frontend

## 1. What you need to provide

| # | What | Where it goes | Needed for |
|---|------|---------------|------------|
| 1 | **Google OAuth Client ID + Client Secret** | `.dev.vars` locally, `wrangler secret put` in production | Google sign-in |
| 2 | **Cloudflare account** (run `npx wrangler login`) | — | Deploying + creating the D1 database |
| 3 | **D1 database id** (auto-generated by `wrangler d1 create`) | `wrangler.toml` | Production database |
| 4 | **R2 bucket name + id** (auto-generated by `wrangler r2 bucket create`) | `wrangler.toml` | Owner photo/document uploads |

| 6 | **Site URL / domain** (e.g. `https://pghunter.in`) | Google Console redirect URI + optional `SITE_URL` var | OAuth callbacks |

For **local development you only need #1 and #5**. D1 + R2 run locally with zero
Cloudflare setup (no account, no login).

## 2. Google OAuth — the only keys you must create

1. Go to <https://console.cloud.google.com/apis/credentials> (create a project if asked, e.g. "PG Hunter").
2. **Create credentials → OAuth client ID → Web application**.
3. Add **Authorized redirect URIs** (both matter):
   - Local: `http://localhost:4321/api/auth/google/callback`
   - Production: `https://<your-domain>/api/auth/google/callback`
4. Copy the **Client ID** and **Client secret**.

Then put them in `.dev.vars` (copy from `.dev.vars.example`):

```env
GOOGLE_CLIENT_ID=xxxx.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=GOCSPX-xxxx
```

If you skip this, email/password auth still works — only the Google button will
show a "not configured" message.

## 3. Local development (no Cloudflare account needed)

```bash
npm install

# Apply the database schema to the local D1 (SQLite) database
# (0001_init.sql = auth + profiles, 0002_owner_admin.sql = owner/admin):
npx wrangler d1 migrations apply pg_hunter --local

# Run the site (Cloudflare runtime + D1 + local R2 emulation):
npm run dev
```

**Admin access locally:** put your email in `.dev.vars` (`ADMIN_EMAILS=you@example.com`),
then register/login with that email — the account is promoted to admin
automatically on the next login. Admins are the only accounts that can open the
admin endpoints.

**Uploads locally:** R2 is emulated by the Cloudflare dev runtime — files land
under `.wrangler/state` with zero setup. Listing images are served publicly at
`/api/media/...`; verification documents are private (only their owner and
admins can read them).

Open <http://localhost:4321>. Register, log in, save PGs, send enquiries —
everything persists in the local D1 file under `.wrangler/state`.

Reset local data: stop the dev server, then `rm -rf .wrangler/state` and
re-apply migrations.

> No `wrangler types` step is needed: `worker-configuration.d.ts` is generated
> by the Cloudflare Vite plugin automatically (and is gitignored + excluded
> from TypeScript — the app ships its own minimal runtime types in
> `src/env.d.ts`).

## 4. Production deploy

First time only:

```bash
# 1. Log in to Cloudflare (opens a browser)
npx wrangler login

# 2. Create the production D1 database
npx wrangler d1 create pg_hunter
# → copy the printed database_id into wrangler.toml ([[d1_databases]])
#   and save. Do NOT leave the placeholder id.

# 3. Create the media bucket (owner uploads, listing photos)
npx wrangler r2 bucket create pg-hunter-media
# → copy the printed bucket_name into wrangler.toml ([r2_buckets] MEDIA)

# 4. Apply the schema to the production database
npx wrangler d1 migrations apply pg_hunter --remote

# 5. Set the secrets (each prompts for a value)
npx wrangler secret put GOOGLE_CLIENT_ID
npx wrangler secret put GOOGLE_CLIENT_SECRET
npx wrangler secret put ADMIN_EMAILS
```

**Admin access in production:** `ADMIN_EMAILS` is a comma-separated list of
emails, e.g. `admin@pghunter.in,rishabh@gmail.com`. Accounts with those emails
are auto-promoted to admin on their next login/register. Anyone else gets 403
from all `/api/admin/*` routes.

Every deploy:

```bash
npm run deploy   # = astro build && wrangler deploy
```

`npm run build` emits the Worker under `dist/server` and static assets under
`dist/client`; `wrangler deploy` automatically redirects to the resolved
`dist/server/wrangler.json` (binding D1 + the ASSETS binding to `dist/client`)
and uploads both as one Worker (`pg-hunter`).

### Custom domain (recommended)

Workers get a free `*.workers.dev` URL, but for Google OAuth + a real product
you want your own domain:

1. In the Cloudflare dashboard → **Workers & Pages → pg-hunter → Settings → Domains & Routes** → add your domain (it must already be on Cloudflare DNS).
2. Google OAuth: if your domain differs from `SITE_URL`, set the var so callback URLs match:
   ```bash
   npx wrangler var set SITE_URL https://pghunter.in
   ```
   (Leave it unset and the Worker derives the origin from each request — correct when the Worker is served from the final domain.)

## 5. API reference (all same-origin, session = `ph_session` cookie)

**Auth + student**

| Method | Path | Body | Notes |
|--------|------|------|-------|
| POST | `/api/auth/register` | `{ name, email, password, role? }` | Creates account + session |
| POST | `/api/auth/login` | `{ email, password }` | Starts session |
| POST | `/api/auth/logout` | — | Destroys session |
| GET | `/api/auth/me` | — | Current user, or 401 |
| GET | `/api/auth/google?next=/profile` | — | Redirects to Google |
| GET | `/api/auth/google/callback?code=…&state=…` | — | Completes sign-in, redirects to `next` |
| PUT | `/api/profile` | `{ name?, phone?, collegeSlug? }` | Updates profile |
| GET | `/api/saved` | — | List of saved property ids |
| POST | `/api/saved` | `{ propertyId }` | Toggle save |
| POST | `/api/enquiries` | `{ propertyId, budget?, moveInMonth?, message? }` | Creates a lead |
| GET | `/api/listings` | `?q=&budget=&roomType=&gender=&sort=` | **Public** — published listings, searchable/filterable/sortable |

**Media (owner/admin)** — multipart `POST` with `file`, `purpose`, optional `listingId`/`docType`

| Method | Path | Body | Notes |
|--------|------|------|-------|
| POST | `/api/media` | `purpose=listing-images \| listing-documents \| verification` | Uploads to R2 (max 10 MB, images + PDF) |
| GET | `/api/media/[...key]` | — | Serves listing images publicly; verification docs only to owner/admin |

**Owner**

| Method | Path | Body | Notes |
|--------|------|------|-------|
| GET | `/api/owner/me` | — | Owner dashboard stats (listings, leads, verification) |
| GET | `/api/owner/listings` | — | The owner's listings (with rooms + media) |
| POST | `/api/owner/listings` | listing object + `rooms[]` | Create a draft listing |
| GET | `/api/owner/listings/:id` | — | One listing (owner or admin) |
| PUT | `/api/owner/listings/:id` | listing object + `rooms[]` | Update a draft |
| DELETE | `/api/owner/listings/:id` | — | Delete + removes R2 objects |
| POST | `/api/owner/listings/:id/submit` | — | Send draft for review (→ `pending`) |
| GET | `/api/owner/leads` | — | Enquiries received on the owner's listings |
| GET | `/api/owner/verification` | — | Verification status + submitted documents |

**Admin** (only accounts in `ADMIN_EMAILS`)

| Method | Path | Body | Notes |
|--------|------|------|-------|
| GET | `/api/admin/stats` | — | Users / listings / leads / verifications / tour counts |
| GET | `/api/admin/listings?status=` | — | All listings, optional status filter |
| PUT | `/api/admin/listings/:id` | `{ status, verificationStatus?, rejectionReason? }` | Approve (`active`) / reject / verify |
| GET | `/api/admin/verifications?status=` | — | Owner verification documents |
| PUT | `/api/admin/verifications/:id` | `{ decision: approved\|rejected, notes? }` | Review a document (approval marks the listing verified) |
| GET | `/api/admin/tours` | — | All room-tour videos |
| POST | `/api/admin/tours` | `{ listingId, videoId, title? }` | Attach a YouTube room tour to a listing |
| DELETE | `/api/admin/tours/:id` | — | Remove a room tour |

## 6. Schema

- `db/migrations/0001_init.sql` — `users`, `sessions`, `saved_pgs`, `leads`
- `db/migrations/0002_owner_admin.sql` — `is_admin` on users, `owner_listings`,
  `listing_rooms`, `media` (photos + YouTube tours), `verification_documents`

Apply with `wrangler d1 migrations apply pg_hunter --local|--remote`.
Add future migrations as `db/migrations/0003_*.sql`.

Room-tour videos are YouTube ids for the MVP (per `/ai/MASTER_ARCHITECTURE.md`
— raw video upload needs Cloudflare Stream, which is deferred). Admins attach
them to listings via `POST /api/admin/tours`; they appear in the listing's
`media[]` alongside owner photos.
